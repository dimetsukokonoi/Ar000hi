Applied changes summary (all verified):
- Auth/verification: DEMO_MODE-gated OTP hint; per-IP+email rate limiting for
  login and OTP verify/resend (5 attempts / 5 min); account-active check in
  token validation; stronger password rule (min 6 chars).
- Driver verification: `GET /api/drivers/pending?status=all|pending|approved|rejected`
  (default pending); upload extension now derived from MIME type.
- Live tracking: 32-hex share token (was 12 hex); session read is owner-only;
  stop on an already-inactive session now 404s; frontend stops polling when the
  ride ends; map gains auto-follow + manual re-center.
- SOS: resolving a missing alert now returns 404.
- Admin complaints: reporter existence is validated.
- Cost splitter: seat-weighted shares with exact (paisa) rounding so breakdown
  always sums to the total; join enforces capacity via `total_seats` (default 4).
- Surge: schedule now flags exactly one `is_current` hour and the live active-ride
  bump applies only to that hour (was bumping all 24).
- Contacts: BD-format phone validation; auto-share now persists to a new
  `contact_shares` table and a share-history endpoint lists it.
- Chat: spam guard (20 msgs / 10 s → close 4429) + 500-char message cap.
- Eco: NULL-distance guard; new top-10 leaderboard endpoint.
- DB: WAL mode + FK indexes; `rides.total_seats` migration; new `contact_shares` table.
- Frontend: rides page rewritten (surge schedule strip, seats, inline errors,
  participant-gated chat), chat 4401/4403 fatal states, contacts share history,
  eco error state + leaderboard, dashboard GPS double-post + interval-leak fixed.

Verification:
- Backend regression: 54/54 checks green on a throwaway DB.
- Live smoke: schedule is_current, total_seats, 32-hex token, share history,
  login rate-limit 429 — all green.
- Frontend: `npx tsc --noEmit`, `npm run lint`, `npm run build` all clean.
- Backend now runs with `--reload` so future changes are picked up automatically.
